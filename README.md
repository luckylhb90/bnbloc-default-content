# bnbloc default content

**The experts, skill packs, prompt packs, AI assists and room templates every organization
of a [bnbloc](https://github.com/luckylhb90/bnbloc) deployment starts
with.**

This is ordinary content. bnbloc ships no prompts: its binaries hold the
capabilities (the assist route and each assist's output contract, the
content kinds, the room tools and their briefs), and an operator publishes
this repository's packages at platform scope, where every member of every
organization finds them in the Library, marked **Default**. Nothing here
is special to the platform: copy a package and change it, publish your
organization's own version under the same name, or keep a member's own.
The nearest version wins (a member's own, then the organization's, then
the default), except for `explain-source-use`, which explains a grant only
an admin decides: the organization's version, else the default, never a
member's copy.

| Package | Kind | What it is |
|---|---|---|
| `expert-builder` | expert | Creates and improves experts, skill packs, prompt packs and assists by conversation (the Library's workshop opens a room with it by name) |
| `app-builder` | expert | Builds interactive apps; wears `interactive-apps`, offers `app-starters` |
| `interactive-apps`, `media-skills` | skill packs | Building apps on the app SDK; making images and audio with the media tools |
| `starters` | prompt pack | The examples above an empty room's composer (`everyRoom: true`: offered in every empty room) |
| `app-starters`, `file-prompts`, `code-prompts`, `diagram-prompts` | prompt packs | App requests; suggestions for a file or a selection in it |
| `team-room`, `project-room`, `release-room`, `support-desk`, `e2e-testing-room` | room packages | Room templates offered under "Start from" in New room: the sections and channels a new room starts with (purposes, rules, who posts, slow mode) |
| `enhance-prompt`, `describe-work`, `describe-room`, `draft-expert`, `draft-skill-pack`, `draft-prompt-pack`, `plan-room`, `draft-schedule`, `explain-source-use`, `review-skill`, `fill-settings`, `suggest-skill-dirs`, `find-a-way` | assists | The prompts behind the web's AI buttons, one per task name |

Each directory of `packages/` is a content package in bnbloc's format
(`component.json`, and `INSTRUCTIONS.md`, skills or a README by kind); the
directory is the package's name.

## What the platform holds you to

- **The format and its limits**, checked by the platform's own validator:
  `bnbloc content check <dir>` (or `--all packages`), the same check a save
  and a platform install make.
- **An assist's output contract.** The web and the gateway run 13 tasks by
  name and read their answers; `bnbloc content contracts` lists what each
  must answer (its output, its fields with their types and item fields,
  its gate, and the closed values the caller acts on). A package under one
  of those names that does not meet it is refused, so a rewritten prompt
  can change the wording, never break the dialog.
- **The platform's facts are not copied here.** Every room's records hold
  the app SDK (`app-sdk/sdk.js` in demo mode and its declarations
  `app-sdk/sdk.d.ts`) and the content limits (`content-limits.md`),
  generated by the platform; the skills point there.

## Check

```sh
go test ./...          # every package against the pinned platform
go tool bnbloc content check --all packages
```

The platform is pinned in `go.mod` (its CLI is a `tool` of this module):
the tests run its validator and contracts and read its SDK declarations
and web sources. CI runs both on every push. While `go.mod` replaces the
platform with a checkout beside this one (`../bnbloc`, until the platform
version these packages need is published), keep that checkout there.

## Publish

As a super admin of the deployment, with your publisher key
(`bnbloc keys gen`, its public half among the deployment's trusted keys):

```sh
scripts/publish.sh --gateway https://<gateway> --rollout auto
# the same as: bnbloc content publish --all packages --gateway https://<gateway> --rollout auto
```

Each package is packed with the platform's packer, validated, uploaded,
pinned in its platform package, signed and installed for every
organization. `--rollout off` installs them unpublished. One package:
`bnbloc content publish --dir packages/<name>`. Publishing again is safe:
a version already installed with the same bytes is kept, and a new
version is added to the same platform row (rooms and jobs pinned to an old
version keep it). Publish each new release of this repository, and on a
fresh deployment right after it starts: until then the AI buttons are
hidden, there are no starters and the workshop has no builder (agents
work regardless).

## Change

Edit a package, bump its `version` (a version installed with other bytes
is refused: publish a newer one), run the tests, open a pull request. A
tag `vX.Y.Z` checks everything again and attaches the set to the GitHub
release (the packages, the platform's check of each with its bundle's
sha256, and `SHA256SUMS.txt`); publishing stays the operator's, signed
with their key. `docs/experience-regression.md` is the check of what
agents can still do with and without this content.
